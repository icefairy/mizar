# 交接（Handoff）

## 何时用

- 一个任务做不完、需要**下次会话继续**时。
- 上下文快满、即将压缩，但当前状态重要、不能丢时。
- 要把工作**交给别人**（或另一个 Agent 会话）接手时。
- 长任务告一段落，想留一个「到此为止、下一步做什么」的锚点。

## 怎么用

1. **生成交接文档**：运行斜杠命令

   ```
   /handoff [可选的备注 / 下一步说明]
   ```

   会在**当前工作目录**写出 `handoff.md`，内容分两层：
   - **会话上下文**：当前任务、会话目标、待办清单、最近对话与工具轨迹（含工具调用与结果）。
   - **环境证据**：git 分支 / 工作区状态 / 最近 10 条提交。

2. **续接**：新会话启动后，首条消息输入

   ```
   @handoff.md 继续
   ```

   新会话据此无缝接上，无需重新解释背景。

## 要点

- **备注写「下一步」**：`/handoff 还剩 X 没做，先修 Y 的边界情况`——比空跑更有用，新会话第一眼就知道该干什么。
- **交接前先提交/暂存**：`handoff.md` 只记录 git 状态快照，未提交的改动请自行 `git add` 或说明，否则新会话看到的"工作区状态"会误导。
- **工具轨迹是重点**：文档会列出「试过什么、结果如何」，避免新会话重复踩坑。
- 非 git 目录也能用，只是缺环境那一层。

## 反模式

- ❌ 上下文已经快满了才想起来交接——此时可能已来不及把关键信息写全。**在还剩余量时就做**。
- ❌ 交接文档里堆满无关历史——它按「最近 40 条」截取，重要结论请写进备注。
